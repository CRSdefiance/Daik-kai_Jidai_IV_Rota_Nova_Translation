# Fleet Info destinations through the dispatch helper

The clean and installed code have six aligned calls to the helper that passes a destination to the Fleet Info writer. Three calls select from the same filtered port list, which only writes indices 0–89. A fourth passes the loop index directly and stops before 114. These four paths exclude the Missionary slot. The other two calls look up neighboring ports around a company's headquarters. The earlier neighbor-list bounds still apply for ordinary headquarters in ports 0–89. Headquarters outside that range remain open. [Exact retail and installed code](../translations/editorial_checkpoints/shared_display_20261123/fleet_destination_inputs_20261124.json)

Two separate writers take the original headquarters byte directly when it is present, and two forward the index of a port object supplied by their caller. The upstream range for those inputs and the initial docking byte in the fallback chain still need evidence. The authored fleet-order fallback also remains open. This pass establishes offline bounds and data flow for the identified paths. [Earlier selector and authored-order checks](editorial_fleet_destination_lists_20261123.md)
