## Loader evidence

The locked ARM9 selector at `0x02053628` chooses a block from the directory's
first global IDs. The loader at `0x020534F4` uses that block and its byte offsets,
copies the selected span and appends a NUL. Whole records can therefore be moved
between blocks by updating the directory and offsets, with executable code intact.
This is static evidence; runtime acceptance remains required.

- Two cache slots start at handle + `0x30`, selected with `slot << 12` at
  `0x02053558` and `0x02053594`; retain the 4,096-byte slot limit.
- Output starts at handle + `0x2030`; the next accessor returns + `0x2230`.
  The research validator conservatively requires copy length plus its NUL to
  stay within that 512-byte interval. This does not replace runtime testing.
- In the clean ARM9, aligned literal references to pathname `0x021435BC`,
  directory `0x0214186C`, size column `0x0214186E`, and offsets `0x02141910`
  occur at file offsets `0x535D0`, `0x5365C`, `0x535D8`, and `0x535D4`
  respectively. An aligned-literal scan alone cannot exclude indirect consumers.
- Disassemblies are saved at `work/analysis/common_cache_functions_clean.txt`
  and `common_cache_constructor_clean.txt`.
