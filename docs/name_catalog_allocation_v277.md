# Current 76-record name allocation catalog: V277 research

V276 refreshed the naming migration against the current registered V275 build.
This turn supplies a compiled, scope-checked runtime catalog for its76 short-slot
records. The research does not create or change a playable ROM; V275 remains
the current integrated candidate.

## Complete prose and formatter recovery

All76 complete source-locked translations compile without shortening words,
names or facts. Five initially fail because a protected paired-character break
would fill the first native row before its internal phase byte. The existing
balanced formatter resolves those five while retaining wording, controls,
macro-length calibration,216-pixel width and the original line limit.
No manually positioned breaks or extra alignment spaces are authored.

The keys come from each selected record's actual V275 bytes; translations remain
locked to the immutable canonical Japanese records and the current reviewed
migration packet. Whole-record and body forms are provided only where the mapped
leading speaker byte is preserved. Exact comparison includes the final NUL.

The76 records produce**131 unique keys**. A census of all**128,492 NUL segments**
in the four route files covers every selected record, with zero conflicting or
unintended route matches. The current**3,668 native COMMON selections** have no
matching catalog keys. This is a resource-string census, not proof of every
possible dynamically generated input. The helper remains restricted to the three
original story copy callers at020242C8,02024310 and02024330.

## Harness defect corrected

The old `loaded()` research utility used a fixed100,000-instruction autoload
budget and did not check that the loader returned. The larger catalog exceeded
that budget. The unfilled staging tail appeared as zero instructions, causing
the later cache monitor to report a nonzero drain operand. Inspection showed
that the saved wrapper was valid but had not been fully loaded into the harness.

The utility now uses the existing size-based budget formula from the independent
ARM9/ARM7 startup verifier. It requires the native loader to return, compares
every full loaded section with the saved source and verifies completion of BSS
clearing. The cache checks are retained. No game code was changed to address
this test-harness failure.
